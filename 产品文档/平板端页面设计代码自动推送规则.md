# 平板端页面设计代码自动推送规则

## 目标

为了避免后续设计平板端页面时，已经确认并实现的页面被误删、覆盖或回退，本项目从本规则建立后，所有 AI 助手执行页面设计、交互调整、样式调整、路由新增、组件修改等代码变动，都必须在完成后形成 Git 检查点，并推送到指定 GitHub 仓库。

这里的 AI 助手包括但不限于：

- Codex
- DeepSeek
- Cursor / VS Code 内其他 AI 编程助手
- 任何被用户要求继续修改本项目代码的 AI 工具

## 固定操作对象

平板端页面设计与实现工作的默认操作分支是：

```text
feat/tablet-ai-entry-page
```

对应远程分支是：

```text
tablet-ocr/feat/tablet-ai-entry-page
```

指定 GitHub 仓库是：

```text
https://github.com/fyzengiris-ops/tablet_ocr_V1.35.git
```

本地 remote 名称固定使用：

```text
tablet-ocr
```

## 开始修改前必须确认分支

任何 AI 助手在修改平板端页面前，必须先确认当前分支：

```bash
git branch --show-current
```

如果当前分支不是 `feat/tablet-ai-entry-page`，必须先切换到该分支：

```bash
git switch feat/tablet-ai-entry-page
```

如果本地没有该分支，需要先拉取远程分支并建立本地跟踪分支：

```bash
git fetch tablet-ocr
git switch -c feat/tablet-ai-entry-page --track tablet-ocr/feat/tablet-ai-entry-page
```

只有用户明确要求“新开一个分支”时，才允许从 `feat/tablet-ai-entry-page` 再创建新的平板端工作分支。新分支创建后，也必须推送到 `tablet-ocr` 仓库。

## 强制执行范围

只要 AI 助手在本项目中改动了代码或会影响预览效果的文件，就必须执行本规则，包括但不限于：

- 新增或修改平板端页面。
- 调整已有页面的布局、样式、文案、交互状态。
- 新增或修改组件、路由、配置、全局样式。
- 为页面预览新增 mock 数据、静态页面或演示入口。
- 修改设计说明、需求文档、页面方案文档，并且该文档会影响后续实现。

不属于本次任务的用户已有改动，不允许被 AI 助手自动纳入提交。

## 每次代码变动后的执行流程

1. 检查当前分支和变动范围。

```bash
git branch --show-current
git status --short
```

当前分支必须是 `feat/tablet-ai-entry-page`，或者是用户明确要求从该分支新开的平板端工作分支。

2. 确认本次任务实际改动的文件，只暂存本次任务相关文件。

```bash
git add <本次任务相关文件>
```

不得使用 `git add .` 直接暂存全部文件，除非已经确认当前工作区没有任何无关改动。

3. 执行必要校验。

前端 TypeScript / 页面改动默认执行：

```bash
pnpm ts-check
```

如果只是 Markdown 文档改动，可以跳过代码校验，但需要在最终说明中写明原因。

4. 创建检查点提交。

提交信息需要能看出页面或步骤范围，例如：

```bash
git commit -m "feat: add tablet ai entry preview page"
```

5. 确认远程仓库地址。

如果本地没有 `tablet-ocr` remote，需要先添加：

```bash
git remote add tablet-ocr https://github.com/fyzengiris-ops/tablet_ocr_V1.35.git
```

如果已经存在，需要确认地址正确：

```bash
git remote get-url tablet-ocr
```

返回结果必须是：

```text
https://github.com/fyzengiris-ops/tablet_ocr_V1.35.git
```

6. 推送当前分支到 GitHub。

```bash
git push -u tablet-ocr <当前分支名>
```

后续同一分支再次提交后，可以直接执行：

```bash
git push
```

## 页面设计保护规则

- 已经完成并确认的页面，后续不得因为设计新页面而删除、覆盖或重写。
- 如果确实需要调整已确认页面，必须先说明调整原因、影响范围和会改动的文件。
- 每完成一个可预览页面或一个关键交互状态，都必须形成一次独立提交。
- 不允许通过 `git reset --hard`、`git checkout -- <file>` 等方式回退用户或历史设计成果，除非用户明确要求。
- 不允许为了修复后续页面的问题，直接删除前面已经完成的页面入口、路由、组件或样式。
- 如果后续实现中发现必须共用组件或全局样式，需要先保证已完成页面的视觉效果不被破坏，再继续抽象。

## 推送失败时的处理

如果因为 GitHub 权限、网络、远程仓库不存在、分支冲突等原因导致推送失败，AI 助手必须停止自动处理，并在最终说明中明确写出：

- 已完成的本地提交哈希。
- 推送失败的原因或错误信息摘要。
- 当前分支名。
- 需要用户处理的事项。

推送失败时，不允许强制推送，不允许删除远程分支，不允许改写已有提交历史。

## 对所有 AI 助手的执行要求

本文件存在后，任何 AI 助手在本项目内执行平板端页面代码或页面设计改动时，默认必须遵守以上流程。用户不需要每次重复提醒“切换到哪个分支”“新建提交”或“推送到 GitHub”。

如果任务只是分析、方案设计、阅读代码、查看截图、整理清单，没有改动项目文件，则不需要提交和推送。
